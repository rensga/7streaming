# Preparación para producción

## Lectura del mercado

Consulta del sitio: 25 de noviembre de 2026. La portada de [LunarShope](https://lunarshope.com/) presenta categorías, productos destacados, comunidad en WhatsApp/Discord y reseñas; sus fichas muestran precio en reales, descuentos, inventario, entrega automática y reseñas. Sus términos mencionan Pix y transferencia bancaria. Es un flujo comercial orientado a Brasil, por lo que Pix no resuelve los cobros locales en Venezuela. Algunos nombres de producto que aparecen en la portada (por ejemplo, “conta … bugada”) no son un estándar que 7streaming deba copiar: solo deben listarse productos legítimos con permiso de distribución verificable.

Para competir con confianza, las funciones valiosas son catálogo filtrable, precio final y moneda visibles, duración, entrega, condiciones, soporte, pedidos rastreables y reseñas verificadas tras una compra real. La interfaz ya cubre búsqueda, categorías, destacados y fichas; exige que las ofertas publicadas tengan los datos comerciales completos y una confirmación de autorización. El administrador puede ajustar las tarjetas de simulación y la referencia de conversión; estos ejemplos no son ofertas. El botón conduce a Telegram para coordinación manual; no es pasarela de pago y no se simulan pedidos, pagos o entregas.

## Antes de aceptar ventas

- **Derechos y catálogo:** confirma por escrito que puedes revender cada producto; publica solo licencias/códigos de distribuidores autorizados. No vendas cuentas compartidas, credenciales, accesos modificados o no autorizados. La casilla del panel es una declaración del operador, no reemplaza la licencia ni la aprobación del proveedor.
- **Identidad y obligaciones locales:** completa nombre legal del operador, RIF, dirección, contacto, facturación, privacidad, términos, cancelaciones y reembolsos con datos reales y revisión legal en Venezuela. Los textos actuales no sustituyen esos documentos.
- **Pago por Telegram:** el botón abre una consulta directa con el usuario público configurado; el comprador y el operador acuerdan disponibilidad, importe exacto, método y condiciones fuera del sitio. Telegram no procesa el pago ni ofrece conciliación comercial para esta tienda; no solicites contraseñas, códigos de verificación ni datos completos de tarjetas. Si luego integras un adquirente, confirma su autorización y usa un checkout alojado con notificaciones verificables.
- **Pedidos y entrega:** registra manualmente cada acuerdo fuera de esta aplicación y define confirmación del pago, comprobante, entrega segura, cancelación, reembolso y soporte antes de vender. El sitio no tiene pedidos, cuenta de cliente, verificación de pago ni entrega automática.
- **Atención y confianza:** configura un correo/teléfono comercial visible y horarios/SLA. Publica reseñas solo después de comprobar una compra; no copies las valoraciones de otra tienda.
- **Infraestructura:** usa TLS, dominio final, secretos fuera del repositorio, backups probados y monitorización. El modo local conserva `data/catalog.json`; el despliegue Vercel usa Firebase Admin/Cloud Firestore para catálogo, precios de simulación, auditoría, sesiones y límites de acceso, con control de concurrencia transaccional.

## Despliegue en Vercel

Importa el repositorio en Vercel y configura Cloud Firestore en un proyecto Firebase (modo nativo). Crea una clave de cuenta de servicio desde Firebase Console → Configuración del proyecto → Cuentas de servicio; añade `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL` y `FIREBASE_PRIVATE_KEY` como variables privadas en Vercel. Mantén proyectos Firebase separados para Preview y Production. Despliega las reglas con `firebase deploy --only firestore:rules --project <project-id>` o copia `firestore.rules` en la sección Rules de Firebase Console. El primer acceso crea el documento de estado y carga `data/catalog.json` como semilla solo si Firestore aún no contiene datos. No uses el almacenamiento local de funciones para datos persistentes. Las reglas deniegan acceso directo desde clientes; Firebase Admin omite esas reglas en las solicitudes de servidor. El adaptador serializa el estado en un documento y limita las escrituras a 900 KB (el máximo de Firestore es 1 MiB); si el catálogo crece, habrá que separar sus colecciones y el historial de auditoría.

Configura `ADMIN_EMAIL` y `ADMIN_PASSWORD` (mínimo 12 caracteres) como variables privadas de producción. La clave PEM de Firebase debe guardarse como secreto; los saltos de línea escapados `\n` se normalizan en el servidor. El dominio asignado por Vercel puede usarse como `APP_ORIGIN`; define el valor en el panel para fijar el dominio canónico. `VITE_TELEGRAM_USERNAME` usa `rensgaaa` por defecto y es público; cámbialo en el entorno de build si luego reemplazas ese usuario. El valor se incorpora al frontend.

Antes de importar el repositorio, verifica localmente con `npm ci` y `npm test`. Vercel ejecuta el build de `vercel.json`; configura las variables anteriores en Project Settings → Environment Variables y vuelve a desplegar.

El endpoint de vida es `/api/health`. Verifica en Vercel la portada, `/catalogo`, la API y una edición de prueba en el panel antes de anunciar el sitio. El enlace `@rensgaaa` solo abre una consulta manual; no cobra, crea pedidos ni confirma pagos. Como todavía no hay ofertas autorizadas, mantén el catálogo sin productos publicables y presenta el lanzamiento como informativo, no como tienda lista para vender.
